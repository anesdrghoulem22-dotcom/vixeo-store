# دكان — منصة بائعين متعددين (Firebase)

منصة بيع اشتراكات ومنتجات رقمية/ملموسة، بواجهتين (زبون وبائع)، تعمل بـ HTML/CSS/JS بدون أي كود خادم (Backend) تكتبه أنت — لكنها تستخدم **Firebase (مجاني)** كقاعدة بيانات حقيقية حتى تكون المنتجات والمتاجر مرئية فعلاً لأي زائر، على أي جهاز أو متصفح.

> ⚠️ هذا التغيير مهم: في نسخة سابقة كان المشروع يعتمد فقط على `localStorage`، وهو تخزين محلي داخل متصفح كل شخص على حدة — لذلك كانت المنتجات التي يضيفها بائع لا تظهر عند أي شخص آخر، ورابط المتجر لا يعمل إلا على نفس المتصفح. النسخة الحالية تحل هذه المشكلة جذرياً عبر Firebase.

## 1) إعداد مشروع Firebase (5 دقائق، مجاني بالكامل)

1. اذهب إلى https://console.firebase.google.com وسجّل الدخول بحساب Google.
2. اضغط **Add project** (إضافة مشروع)، اختر اسماً (مثلاً `dukan-store`)، أكمل الخطوات (يمكن تعطيل Google Analytics، غير ضروري).
3. من القائمة الجانبية اذهب إلى **Build → Authentication** → اضغط **Get started** → فعّل مزوّد **Email/Password**.
4. من القائمة الجانبية اذهب إلى **Build → Firestore Database** → اضغط **Create database** → اختر **Start in production mode** → اختر أقرب موقع خادم لك.
5. بعد إنشاء قاعدة البيانات، اذهب لتبويب **Rules** والصق القواعد التالية بالضبط، ثم اضغط **Publish**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ضع هنا نفس البريد الموجود في ADMIN_EMAILS داخل js/db.js
    function isAdmin() {
      return request.auth != null
             && request.auth.token.email in ['ivoraivora138@gmail.com'];
    }
    function isOwner(sellerId) {
      return request.auth != null && request.auth.uid == sellerId;
    }

    match /sellers/{sellerId} {
      allow read: if true;
      allow write: if isOwner(sellerId) || isAdmin();
    }

    match /products/{productId} {
      allow read: if true;
      allow create: if request.auth != null && request.resource.data.sellerId == request.auth.uid;
      allow update, delete: if request.auth != null && resource.data.sellerId == request.auth.uid;
    }

    match /orders/{orderId} {
      allow create: if true;
      allow read: if (request.auth != null && request.auth.uid in resource.data.sellerIds) || isAdmin();
      allow update: if (request.auth != null && request.auth.uid in resource.data.sellerIds) || isAdmin();
    }

    // الموظفون — خاصة بصاحب المتجر وحده
    match /staff/{staffId} {
      allow read, update, delete: if request.auth != null && resource.data.sellerId == request.auth.uid;
      allow create: if request.auth != null && request.resource.data.sellerId == request.auth.uid;
    }

    // القائمة السوداء — البائع يديرها، والزبون يحتاج قراءة للتحقق عند الطلب
    match /blacklist/{itemId} {
      allow read: if true;
      allow create: if request.auth != null && request.resource.data.sellerId == request.auth.uid;
      allow update, delete: if request.auth != null && resource.data.sellerId == request.auth.uid;
    }

    // الكوبونات — قراءة عامة للتحقق، وتعديل لصاحب المتجر
    // (update مسموح للزبون لتحديث عدّاد الاستعمال فقط)
    match /coupons/{couponId} {
      allow read: if true;
      allow create, delete: if request.auth != null && request.resource.data.sellerId == request.auth.uid;
      allow update: if (request.auth != null && resource.data.sellerId == request.auth.uid)
                    || request.resource.data.diff(resource.data).affectedKeys().hasOnly(['used']);
    }

    // محاولات الطلب من أرقام محظورة (ينشئها الزبون، يقرأها التاجر)
    match /blacklist_attempts/{attemptId} {
      allow create: if true;
      allow read, update, delete: if request.auth != null && resource.data.sellerId == request.auth.uid;
    }

    // عدّاد الزيارات
    match /visits/{visitId} {
      allow read: if request.auth != null;
      allow create, update: if true;
    }
  }
}
```

هذه القواعد تسمح لأي زائر بقراءة المنتجات والمتاجر (حتى يظهر المتجر للجميع)، لكنها تمنع أي شخص من تعديل منتجات ليست له، ومن قراءة طلبات ليست متعلقة بمتجره.

6. من القائمة الجانبية اذهب لإعدادات المشروع (⚙️ **Project settings**) → في تبويب **General** انزل لقسم **Your apps** → اضغط أيقونة **Web (</>)** لإنشاء تطبيق ويب → أعطه اسماً واضغط **Register app**.
7. ستظهر لك بيانات `firebaseConfig` — انسخها والصقها في ملف `js/firebase-config.js` داخل المشروع، مكان الأسطر التي تبدأ بـ "ضع...".

بعد هذه الخطوات، ارفع مجلد `dukan` على أي استضافة (حتى استضافة ملفات ثابتة مجانية مثل GitHub Pages أو Netlify أو Firebase Hosting نفسها)، أو شغّله محلياً:
```bash
cd dukan
python3 -m http.server 8000
```

## إصلاحات وتفعيل حقيقي لمزايا الاشتراك (آخر تحديث)

**📈 الزيارات:** كانت تُحسب بتوقيت UTC (فرق ساعة عن الجزائر، يُخطئ إسناد زيارات منتصف الليل لليوم الخطأ)، والرسم البياني كان يعرض فقط الأيام التي صادف وجود زيارات فيها فيبدو متقطعاً. الآن التاريخ محلي، والرسم يعرض دائماً 14 يوماً متتالياً كاملة (بقيمة صفر للأيام بلا زيارات).

**🔔 جرس التنبيهات:** أصبح قائمة منسدلة حقيقية تعرض الطلبات الجديدة، تنبيهات المخزون، ومحاولات الأرقام المحظورة — بدل الاكتفاء بالانتقال لتبويب "نظرة عامة" بصمت.

**⭐ ظهور مبكر (خطتا بلس وبرو):** منتجات البائعين المشتركين في هاتين الخطتين تظهر أولاً فعلياً في `market.html`، محسوبة من حالة اشتراكهم الفعلية لحظة التحميل — وليست وصفاً تسويقياً فقط.

**✓ علامة "متجر موثّق" (خطة برو فقط):** تظهر فعلياً بجانب اسم المتجر في صفحته الخاصة، بجانب اسم البائع في صفحة المنتج، وكعلامة صغيرة على بطاقات منتجاته في المتجر العام.

**📦 حد الطلبات الشهري:** أساسي 30 طلباً/شهر، بلس 100 طلباً/شهر، برو **بلا حد**. عند وصول البائع للحد، أي طلب جديد من الزبائن يُرفض تلقائياً برسالة واضحة توجّههم للتواصل المباشر. شريط تقدّم في لوحة التحكم يعرض الاستهلاك الحالي (يتحول لأحمر عند 80% فأكثر) مع رابط ترقية.

**👥 حد الموظفين:** أساسي موظف واحد، بلس حتى 3، برو بلا حد. يُمنع إضافة موظف جديد عند بلوغ الحد مع رسالة توضيحية.

## تجربة نظام البائعين

1. من `index.html` اضغط **"أنا بائع"** → `register.html` (بريد إلكتروني حقيقي الصيغة، كلمة مرور 6 أحرف فأكثر، رقم واتساب اختياري).
2. تبدأ فترة تجريبية **7 أيام**، مرتبطة "ببصمة" هذا المتصفح محلياً (localStorage) لمنع فتح تجربة ثانية من نفس الجهاز — هذا الجزء فقط يبقى محلياً لأنه لا يحتاج مشاركة بين المستخدمين.
3. في `dashboard.html`: صورة/Avatar وزر تسجيل خروج، عداد تنازلي **حي** (HH:MM:SS)، زر "نسخ رابط المتجر" (يعمل الآن فعلياً لأي شخص تشاركه معه، لأن البيانات في Firebase).
4. أضف منتجاً: التصنيف، **النوع** (رقمي ⚡ / ملموس 🚚)، السعر، المخزون، صورة (رفع ملف يُحوَّل Base64 — بحد أقصى تقريبي 700KB بسبب حدود حجم مستند Firestore — أو الصق رابط صورة جاهزاً بدون حدود حجم).
5. أي زائر آخر (على أي جهاز) يفتح `market.html` أو رابط `store.html?seller=ID` الآن **يرى هذه المنتجات فعلياً**.

## الاشتراك عبر واتساب (بدون تفعيل تلقائي)

في `pricing.html`، الضغط على "اشترك عبر واتساب" (شهري 2,000 / سنوي 18,000 د.ج) **لا يُفعِّل شيئاً تلقائياً** — يفتح محادثة واتساب جاهزة على `+213558593252` بتفاصيل الطلب. **التفعيل الفعلي بعد تأكيد الدفع يتم يدوياً من طرفكم** عبر Firebase Console:
1. اذهب لمشروعك في Firebase Console → **Firestore Database** → مجموعة `sellers` → افتح مستند البائع (يمكن البحث بالبريد الإلكتروني عبر تبويب Data).
2. عدّل الحقل `subscription` يدوياً ليصبح مثلاً:
   ```json
   { "active": true, "plan": "monthly", "start": 1234567890000, "end": 1237246290000 }
   ```
   (`start`/`end` بصيغة timestamp بالمللي ثانية — يمكن حسابهما بسهولة أو استخدام `Date.now()` في console المتصفح).


## لوحة الإدارة (admin.html) — تفعيل الاشتراكات

بدل تعديل Firestore يدوياً، افتح `admin.html` وسجّل الدخول ببريد المشرف.

**الإعداد لمرة واحدة:**
1. في `js/db.js` ضع بريدك في `ADMIN_EMAILS` (مضبوط حالياً على `ivoraivora138@gmail.com`).
2. في قواعد Firestore أعلاه ضع **نفس البريد** داخل دالة `isAdmin()`.
3. يجب أن يكون لك حساب بائع مسجّل بنفس هذا البريد في الموقع (سجّل عادياً من `register.html`).

**الاستعمال:** افتح `admin.html` → اكتب بريد البائع بعد تأكيد الدفع → اختر الخطة (شهري 1,000 د.ج / سنوي 9,000 د.ج) → اضغط "تفعيل الاشتراك". يحسب التواريخ تلقائياً بالصيغة الصحيحة (number بالمللي ثانية) بلا أي حساب يدوي.

الجدول أسفل الصفحة يعرض كل البائعين وحالتهم (تجريبي / مشترك / منتهي) مع بحث بالبريد أو الاسم، وأزرار تفعيل وإلغاء مباشرة لكل بائع.

**تنبيه أمني:** حصر الوصول يعتمد على قواعد Firestore (`isAdmin()`)، وهي التي تمنع فعلياً أي شخص آخر من تعديل الاشتراكات — الإخفاء في الواجهة وحده لا يكفي، لذا لا تتجاهل الخطوة 2.


## الميزات المتقدمة في لوحة التحكم

**📊 الإحصائيات** — زيارات آخر 30 يوم برسم بياني، إجمالي الطلبات والمبيعات، نسبة التحويل، متوسط قيمة الطلب، الطلبات المكتملة والملغاة، وأكثر 5 منتجات مبيعاً.

**🎟️ كوبونات الخصم** — أنشئ أكواد خصم بنسبة مئوية أو مبلغ ثابت، مع حد أدنى للطلب، أقصى عدد استعمالات، وتاريخ انتهاء. الزبون يدخل الكود في السلة فيُطبَّق الخصم تلقائياً، ويُحتسب في رسالة الواتساب. الكوبون يعمل على منتجات متجر واحد في الطلب.

**👥 فريق العمل** — أضف موظفين بصلاحيات محدودة ومخصصة (7 صلاحيات: عرض الطلبات، تأكيد الطلبات، عرض/إدارة المنتجات، الكوبونات، القائمة السوداء، الإحصائيات)، مع إمكانية إيقاف أي موظف مؤقتاً.

**🚫 القائمة السوداء** — أضف أرقام العملاء الذين يرفضون استلام طلبات COD. أي طلب جديد من رقم محظور **يُرفض تلقائياً** قبل تسجيله، لحمايتك من خسائر الشحن.

**📢 التسويق والبيكسل** — اربط متجرك بـ Facebook Pixel، TikTok Pixel، Snapchat Pixel، Google Analytics، وGoogle Tag Manager. الأكواد تُحقن تلقائياً في صفحة متجرك، وتُطلق أحداث `ViewContent` عند الزيارة و`Purchase` عند إتمام الطلب.

**📦 تتبع المخزون** — المخزون يُخصم تلقائياً عند كل طلب. تظهر تنبيهات في أعلى لوحة التحكم عند نفاد أي منتج أو وصوله لـ 5 قطع أو أقل، مع مؤشر ملوّن في جدول المنتجات.

**🔔 تنبيه محاولات المحظورين** — إذا حاول رقم من القائمة السوداء تقديم طلب، يُرفض الطلب **ويُسجَّل التنبيه** ليظهر للتاجر في أعلى لوحته مع رقم المحاول وتاريخ المحاولة.

**حالات الطلب:** قيد الانتظار ← قيد التوصيل ← تم التسليم / ملغى.

**⛔ حظر المتجر عند انتهاء الاشتراك** — بدل التحويل الصامت، تظهر شاشة حظر حمراء كاملة تمنع الوصول للوحة التحكم مع عرض الخطط وزر تجديد مباشر. كما يظهر شريط تحذير أحمر بعدّاد تنازلي حي في آخر 3 أيام قبل الانتهاء.

## دورة طلب الزبون (رقمي مقابل ملموس)

- منتج ملموس في السلة ← حقول إجبارية إضافية: الولاية والعنوان.
- منتجات رقمية فقط ← الاسم ورقم الهاتف كافيان.
- عند التأكيد: يُحفظ الطلب في Firestore (مرئي لصاحب المتجر في لوحة تحكمه من أي جهاز)، ثم يُفتح واتساب تلقائياً برسالة جاهزة — لبائع المنتج إن كان رقمه مسجلاً، وإلا رقم المنصة العام.

## إعدادات الحساب (`settings.html`)

- تغيير صورة الحساب (Avatar)، اسم المتجر، رقم واتساب المتجر.
- تغيير كلمة المرور (يتطلب إدخال كلمة المرور الحالية، وفق متطلبات أمان Firebase).

## ملاحظات هامة

- المصادقة الآن حقيقية عبر Firebase Authentication — لا حاجة لأي تشفير يدوي، وكلمات المرور لا تُخزَّن أبداً في قاعدة بياناتك مباشرة.
- التجربة المجانية وقفل الجهاز يبقيان معتمدين على `localStorage` فقط (وهذا مقصود، فهي بيانات جهازية بطبيعتها) — تفريغ بيانات المتصفح يُعيد تفعيل تجربة جديدة على نفس الجهاز.
- السلة (`cart.html`) تبقى محلية أيضاً لأنها بيانات شخصية مؤقتة لكل زائر قبل إتمام الطلب.
- الصور المرفوعة كملفات تُخزَّن Base64 داخل مستند Firestore (حد ~700KB)، لذا يُفضَّل استخدام رابط صورة مباشر للصور الكبيرة.
- إن ظهرت رسالة "تعذّر تحميل..." في أي صفحة، تأكد أن `js/firebase-config.js` معبّأ ببيانات مشروعك الفعلية وأن قواعد Firestore أعلاه منشورة (Published) بالضبط.
